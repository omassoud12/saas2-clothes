# Products — layout and color UI/UX audit

Date: 2026-09-29. Visual audit only; no application changes.
Evidence: current Products JSX/CSS and the offline screenshots generated by the
preceding re-audit. Reviewed catalog/create/details, dense color groups, bulk
pricing, pending cost and confirmation at desktop, tablet and mobile widths.
No new browser suite or live data mutations were needed for this visual review.

The palette is coherent and the simple creation form is compact. The main issue
is hierarchy and repeated containers, rather than needing more decorative colors.
The following priorities are UX judgments, not newly discovered accounting bugs.

## Findings

1. **P2 — Repeated containers make details tall.** White page panel, pale color
   panel and white size cards create three visual layers. Each size repeats state,
   Stock, Price, three controls and More. The two-color/16-size desktop fixture
   is about 1,470px tall. Prefer one compact matrix per color with size, stock
   stepper and price on one row; expand SKU/edit fields locally. Mobile can wrap
   to a compact two-column arrangement without shrinking controls or text.
   Evidence: compact-colors-1366; products.css:245, :249.

2. **P2 — Related actions are scattered.** Back, product header, standalone bulk
   price action, option section and standalone photo disclosure sit in separate
   vertical blocks. Keep identity, Edit and Photo together, and place common
   pricing beside the Colors & sizes heading. Keep Deactivate visually secondary
   and separated from frequent stock actions. Evidence: detail-768, cost-pending-390;
   ProductsPage.jsx:358, :364, :389.

3. **P2 — Tablet/mobile catalog has unnecessary row height.** Desktop is a clear
   table, but the 1024px layout redistributes data into widely separated rows;
   mobile adds a separate footer solely for View product. Put identity/category
   together, stock and price together, and a clearly labeled opening action in
   the same compact card. Avoid making the entire card a hidden click target.
   Evidence: catalog-1024 and catalog-390; products.css responsive card rules.

4. **P2 — Search and Apply compete visually.** Both are filled green actions
   in one filter area; Add product is also green. Users need to understand whether
   Search and Apply submit different criteria. Prefer one clearly named submit
   action for the filter set; keep Clear quiet. Add product remains the primary
   page action. Evidence: catalog-1366, catalog-1024; ProductsPage.jsx filter form.

5. **P2 — Pending-cost link breaks the palette and state hierarchy.** Cost pending
   is a plain anchor, rendered browser blue in the current screenshot. The CSS
   colors a span, but the element was changed to an anchor. Sellable is subdued
   gray text, Active is green, and pending information lacks a consistent badge.
   Use a named amber pending style with readable text and an explicit Inventory
   link. Keep sellability independent: missing cost does not mean unable to sell.
   Evidence: cost-pending-390; ProductsPage.jsx:375; products.css:290.

6. **P2 — Focus and field boundaries are visually weak.** The pale input border
   is only 1.79:1 against white; the generic 28%-opacity green focus outline is
   about 1.52:1 when composited on white. Increase the contrast of functional
   boundaries and keyboard focus. Decorative card borders can remain softer.
   Inputs have their own focused border/outline and disclosure summaries have
   a darker focus rule, so the generic outline calculation is not a finding
   against every individual control. Evidence: index.css:38, :293; products.css:11.

7. **P3 — Small supporting text becomes harder to scan.** Creation labels are
   12px, notes 11px, Remove color 11px, Active badges 11px. The page is compact,
   but repeated secondary labels should not require careful reading. Prefer
   13–14px working text; gain density by removing repeated labels/containers.
   Evidence: create-390; products.css:56, :214, :223, :228.

8. **P3 — Color identity is text-only.** Black/Navy/etc. headings do not provide
   swatches or a consistent visual selector. Add small swatches for the known
   preset palette, always retaining names; custom colors need a neutral fallback.
   Avoid relying on color alone or interpreting arbitrary user text as CSS.
   Evidence: create-390 and detail-768; ProductCreateForm.jsx colorChoices.

## What works

- White surfaces, dark green navigation and restrained red destructive actions.
- Clear selected-size fill; size names remain visible without relying on color.
- Simple creation fits the tested desktop and 390px mobile fixture.
- Product photo/title/actions header is much tighter than the previous layout.
- Destructive confirmation uses a clear red action, explanatory copy and Cancel.
- The preceding responsive suite passed covered no-horizontal-overflow checks.

## Recommended direction

Keep the existing green identity. Use white for working surfaces, one neutral
page background, green for primary actions/success, amber for pending states and
red for destructive actions. Establish one consistent toolbar and compact color
matrix before adding decoration. Prioritize reducing repeated vertical content,
then state/link consistency and focus visibility, then typography and swatches.

This audit does not require eliminating all whitespace or fitting arbitrary
numbers of colors/options on one screen. No code, migrations, business data,
protected PDF, commit or deployment changed. Only this report was added.
